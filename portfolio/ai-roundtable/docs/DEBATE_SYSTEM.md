# AIディベートシステム

この文書はMVP後の将来仕様です。現在は未実装です。

## 目的

回答数を増やすのではなく、主張の弱点、見落とし、根拠、不確実性を明らかにし、人間の判断材料を改善します。多数決だけで結論を決めません。

## 基本フロー

1. ユーザーが質問する
2. 各AIが独立して初回回答する
3. 必要な範囲で他AIの回答を共有する
4. 各AIが正しい点、弱点、誤りの可能性、見落としを評価する
5. 各AIが回答を修正する
6. 停止条件内で追加ラウンドを行う
7. 議長AIが一致点、相違点、根拠、不確実性、追加確認事項、最終提案をまとめる

## モード

- ライト: 初回回答を議長AIが1回まとめる
- レビュー: 他回答を1回評価し、各AIが修正版を出す
- ディベート: 複数ラウンドの反論と修正を行う

低コストなライトから実装・評価し、必要性が確認されてから拡張します。

## 役割

- 賛成役: 案の成立条件と利点を検討
- 反対役: 反例、リスク、失敗条件を検討
- 専門家役: 特定分野の観点と確認すべき一次情報を提示
- 議長役: 論点を整理し、根拠の質と未解決点を明示

役割は視点を与えるもので、回答の正しさや資格を保証しません。

## 制御項目

- 参加AI、役割、議論回数
- ラウンド・AI・全体の最大トークンまたは出力単位
- 質問・セッション・月間の予算上限
- タイムアウト、再試行、ユーザー中断
- 高性能・節約モデルの選択

## 停止条件

- 最大ラウンド、最大利用量、予算、時間のいずれかへ到達
- 新しい論点や修正が一定ラウンド生まれない
- 同じ主張の繰り返しを検出
- 必要なAIが失敗し、継続価値がない
- ユーザーが停止する

無限ループを防ぐため、明示的上限なしのディベートは禁止します。

## 出力

- 初回・修正版回答、各レビュー
- 意見一致点・相違点
- 根拠の強さと独立性
- 不確実性、矛盾、追加確認事項
- 議長AIの提案とその条件
- 参加できなかったAI、停止理由、利用量、概算料金

## ログと将来案

ラウンド、役割、モデル、プロンプト版、入力、出力、停止理由、費用を必要な保存期間だけ記録します。将来はユーザーが途中で論点追加、役割変更、停止、採否判断に参加できるようにします。保存と共有にはプライバシー・認可設計が必要です。
