# プラグインシステム

この文書は将来の拡張方針です。MVPで汎用プラグイン基盤を実装する計画ではありません。

## 対象

- AI: OpenAI、Gemini、Claude、将来のAI、社内AI、役割別AI社員
- 能力: Web検索、ファイル解析、音声、画像、外部サービス連携

## 基本方針

各プロバイダーのSDK、認証、モデル名、エラー、利用量の違いをアプリ全体へ漏らさず、内部の共通リクエスト・レスポンスへ変換します。

```text
AIRequest → Provider.generate() → AIResponse
```

共通情報は質問、システム指示、最大出力、タイムアウト、内部モデル指定、メタデータです。応答は内容、状態、プロバイダー、実モデル、利用量、応答時間、エラーを返します。ストリーミング、画像など固有能力は能力フラグで表し、最低共通機能へ無理に押し込みません。

## 追加時の要件

- 設定と秘密情報を独立して扱う
- タイムアウト、キャンセル、エラー変換、利用量取得を実装する
- 共通契約テストとプロバイダー固有テストを追加する
- SDK型をAPI・比較・保存層へ露出させない
- 対応モデル、価格、能力、停止状態を [MODELS](MODELS.md) で管理する
- 外部送信データと権限を利用者へ説明する

## 安全性

検索・ファイル・外部操作のプラグインには最小権限、入力検証、出力の信頼境界、監査ログ、利用上限、ユーザー確認を設けます。AIの文章だけで重要操作を自動承認しません。

## MVPでのYAGNI

OpenAI接続で最小のサービス境界を作り、Gemini・Claude追加時に実際に共通する部分だけを抽出します。動的ロード、マーケット、複雑なマニフェスト、独自SDKは需要と安全要件が確定するまで作りません。
