# セキュリティ

## 現在の基本ルール

- ローカルのAPIキーはプロジェクト直下の `.env` に置く
- `.env` を `.gitignore` から外さない
- APIキーをコード、HTML、JavaScript、テスト、文書、ログ、エラーへ含めない
- `.env` の実値を共有・表示せず、例にはダミー値だけを使う
- 本番では環境変数または秘密情報管理サービスを使う

## APIキー漏洩時

1. 該当キーを提供元で直ちに無効化する
2. 新しいキーを発行し、安全な保管先だけを更新する
3. Git履歴、ログ、成果物、共有先への拡散範囲を確認する
4. 不正利用と料金を確認し、必要なら提供元へ連絡する
5. 原因と再発防止を記録する

Git履歴から文字列を消すだけではキーは安全にならないため、必ず失効させます。

## 入力・出力とログ

- サーバー側で型、長さ、形式を検証する
- ユーザー入力とAI出力を未加工HTMLとして描画しない
- ファイル対応時はサイズ、形式、マルウェア、保存期間を制限する
- プロンプトインジェクションを前提に、秘密情報や不要な権限をAIへ渡さない
- ログにキー、認証情報、質問全文、個人情報を無条件に出さない
- 相関ID、状態、時間など診断に必要な最小情報を記録する

## API保護

- 外部APIへタイムアウトと制限付き再試行を設定する
- ユーザー・IP・セッション単位のレート制限を公開前に導入する
- リクエスト、日次、月次の利用上限と緊急停止手段を用意する
- CORSは必要なオリジン、メソッド、ヘッダーだけを許可する
- 認証後もリソース単位の認可と所有権を確認する
- セッション、Cookie、CSRFの設定は認証方式に合わせて見直す

## データと依存関係

- 保存データを目的達成に必要な最小限へ限定する
- 保存目的、期間、削除、エクスポート、第三者AIへの送信を明示する
- 機密度に応じて通信・保存時暗号化とアクセス制御を行う
- 依存を最小化し、脆弱性・ライセンス・更新停止を定期確認する
- ロックまたは再現可能な依存管理方法を公開前に決める

## 公開前チェックリスト

- [ ] `.env` と秘密情報がGit履歴・成果物にない
- [ ] 本番デバッグ表示を無効化した
- [ ] 入力検証、安全な出力、CORSを確認した
- [ ] 認証・認可・セッションを確認した
- [ ] レート制限、予算上限、タイムアウト、停止手段がある
- [ ] ログ、監視、アラートに秘密情報がない
- [ ] 保存期間、削除、バックアップ、障害対応を定義した
- [ ] 依存脆弱性と外部API権限を確認した
- [ ] 高リスク回答の注意表示を確認した

脆弱性の非公開報告窓口は公開前に決定します。
