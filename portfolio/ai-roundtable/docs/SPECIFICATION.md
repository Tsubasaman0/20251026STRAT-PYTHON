# 仕様

この文書では `現在`、`MVP予定`、`将来` を明示します。未確定事項を実装済みとして扱いません。

## 現在の仕様

### 画面

- `GET /` で日本語の質問画面を表示する
- 質問は前後の空白を除いた1〜2,000文字
- 文字数、送信中表示、結果、入力・通信エラーを表示する
- 送信中はボタンを無効化する
- 受信した質問を改行を保って安全に描画する

### API

`POST /api/questions` は外部API接続前のエコーAPIです。

```json
{ "question": "FastAPIとは？" }
```

成功時 `200`:

```json
{ "question": "FastAPIとは？" }
```

空白のみ、2,000文字超、型不正は `422`、予期しない内部エラーは `500` です。

## MVP機能仕様（予定）

1. 質問と品質モードを受け付ける
2. OpenAI、Gemini、Claudeへタイムアウト付きで並列送信する
3. AIごとの成功、失敗、タイムアウトを独立表示する
4. 成功回答を比較・要約する
5. 利用量、モデル、応答時間、質問単位の料金概算を表示する

### AI回答の表示形式

各カードにプロバイダー、モデル、状態、回答、応答時間、入力・出力使用量、概算料金、再試行操作を表示します。AIが1社だけ成功した場合も、その回答を失わず表示します。

### 比較・要約の表示形式

- 共通点と相違点
- 各案のメリットとデメリット
- 根拠、不確実性、矛盾
- 推奨案と適用条件
- 判断時の注意点と追加確認事項

多数決だけで推奨を決めません。生成結果と元回答を区別します。

### コスト表示

プロバイダー別、議長AI、合計の概算を表示し、価格基準日・通貨・概算であることを示します。正本は [COST_MANAGEMENT](COST_MANAGEMENT.md) です。

### APIエンドポイント案

| Method / Path | 状態 | 目的 |
| --- | --- | --- |
| `GET /` | 現在 | 質問画面 |
| `POST /api/questions` | 現在 | エコー疎通確認 |
| `POST /api/roundtables` | 案 | 会議を開始 |
| `GET /api/roundtables/{id}` | 案 | 長時間処理の状態・結果を取得 |

長時間化するまでは同期APIを優先し、キューは必要性が確認されてから導入します。

### エラーとローディング

- 入力不備は修正方法を示す
- プロバイダー名、失敗種別、再試行可否を示す
- 内部情報やキーを利用者向けエラーへ含めない
- 全体処理中とAIごとの状態を区別する
- タイムアウト後も成功済み回答を保持する

## 入出力データ案

```text
RoundtableSession
├── id: UUID
├── question: string
├── mode: string
├── status: pending | running | completed | partial | failed
├── responses: list[AIResponse]
├── synthesis: Synthesis | null
└── cost_summary: CostSummary

AIResponse
├── provider / model / content
├── status: completed | failed | timeout
├── input_units / output_units
├── latency_ms
└── estimated_cost
```

金額は浮動小数点を避け、時刻はUTCで保存する方針です。

## 非機能要件

- 秘密情報をサーバー側だけで扱う
- 外部APIなしで主要ロジックをテストできる
- 部分失敗、タイムアウト、制限付き再試行を扱う
- 不要な個人情報と質問全文をログへ残さない
- AI出力を未加工HTMLとして表示しない
- アクセシビリティとモバイル表示を維持する

## 将来仕様

履歴、認証、ファイル入力、出力、ディベート、プラグイン、フィードバック、AI社員モードを含みます。確定仕様へ昇格するまでは [FUTURE_IDEAS](FUTURE_IDEAS.md) または各専門文書で管理します。
